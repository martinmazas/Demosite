[2026-06-01] BUG-001 | Severity: Medium | Status: Open
Title: reCAPTCHA validation failure on user registration despite completed form
Description: During the user registration flow, an intermittent issue occurs where all required fields are correctly filled and the Register button is clicked, yet the application displays the error message "Please verify reCaptcha to register!" and prevents the user from completing registration. The reCAPTCHA widget appears to fail silently or its completion state is not being recognized by the form submission handler.
Steps to Reproduce:
  1. Navigate to the registration page.
  2. Fill in all required fields with valid data.
  3. Click the "Register" button.
Expected Result: User is successfully registered and redirected to the profile page.
Actual Result: Error message "Please verify reCaptcha to register!" is displayed and registration is blocked.
Notes: Issue is intermittent and does not occur on every attempt.

[2026-06-01] BUG-002 | Severity: High | Status: Fixed
Title: Delete user API test fails with 204 Unauthorized despite valid generateToken call
Description: The delete user API test calls generateToken successfully (HTTP 200) then calls DELETE /Account/v1/User/{UUID} with the returned Bearer token, but receives HTTP 204 (Unauthorized) and the user is not deleted. The root cause is that the DemoQA GenerateToken endpoint always returns HTTP 200 even on failure — when a user no longer exists on the server the response body contains token: null. The post<T> method only validates the HTTP status code, so a 200 with token: null passes through silently and the subsequent DELETE is made with Authorization: Bearer null.
Steps to Reproduce:
  1. Run: npx playwright test auth.api.test.ts --grep "Delete user"
  2. getRandomUser(true) picks a user from user.json (skipping the first)
  3. generateToken is called for that user — returns HTTP 200 with token: null (user no longer on server)
  4. deleteUser is called with the null token — Authorization: Bearer null is sent
Expected Result: DELETE /Account/v1/User/{UUID} returns HTTP 200 with { "code": 0, "message": "User deleted successfully." }
Actual Result: DELETE /Account/v1/User/{UUID} returns HTTP 204 — user is not deleted.
Affected Files: fixtures/BaseAPI.ts (generateToken), .auth/user.json (stale users)
Root Cause (Revised): The delete<T> method in BaseAPI.ts was checking for status 200 as success, but the DemoQA DELETE /Account/v1/User/{UUID} endpoint returns 204 (No Content) on successful deletion. The test was incorrectly treating a valid 204 success response as an unauthorized error.
Resolution: Added expectedStatus parameter to the delete<T> method in fixtures/BaseAPI.ts (default 200). Updated deleteUser to pass expectedStatus: 204, matching the actual API contract. Deletion is confirmed by a follow-up getUserProfile call which rejects with "User not found!" after successful deletion.
Fixed in: fixtures/BaseAPI.ts
